\section*{摘\quad 要}
\addcontentsline{toc}{section}{摘要}

本项目实现了一个跨平台的局域网 P2P 文件传输系统，采用 C++17 编写，前端为微信风格的 Web 聊天界面。系统实现了基于 UDP 组播的零配置设备自动发现、基于 TCP 滑动窗口协议的可靠文件传输（窗口大小 16，分片大小 64KB）、基于 RFC 1321 的 MD5 文件完整性校验、基于 ECDH（secp256r1 椭圆曲线）的密钥协商与 MAC 报文鉴别防伪造机制、以及 zlib 透明压缩传输。系统采用四层架构（发现层、信令层、传输层、Web 层），各层通过回调函数解耦，每个服务运行在独立线程中。实验结果表明，本系统能够在局域网环境下实现高效、安全、可靠的点对点文件传输，滑动窗口协议在 100ms 延时网络下吞吐量可达 11.2 MB/s。

\vspace{1em}
\noindent\textbf{关键词：}P2P 文件传输；滑动窗口协议；UDP 组播发现；MD5 校验；ECDH 密钥交换；跨平台网络编程

\section{项目概述}

\subsection{项目背景与目标}

在局域网办公、实验室协作等场景中，经常需要在不同设备之间快速传输文件。传统的文件共享方式（如 U 盘拷贝、网盘中转、即时通讯软件）存在操作繁琐、依赖互联网、传输速度受限等问题。本项目旨在设计并实现一个局域网内的 P2P 文件传输工具，具备以下核心特性：

\begin{itemize}
    \item \textbf{零配置自动发现：}设备启动后自动通过 UDP 组播发现局域网内其他运行本程序的设备，无需手动输入 IP 地址。
    \item \textbf{可靠文件传输：}基于自定义滑动窗口协议在应用层实现流量控制与超时重传，支持断点续传和 MD5 完整性校验。
    \item \textbf{安全通信：}基于 ECDH 密钥交换协商会话密钥，使用 MAC 报文鉴别码防止消息伪造与篡改。
    \item \textbf{微信风格 Web 界面：}内置 HTTP 服务器提供 REST API 和静态前端，用户可通过浏览器进行操作，支持设备列表、聊天气泡、文件进度条。
    \item \textbf{跨平台兼容：}使用 C++17 和 CMake 构建系统，支持 Linux、Windows、macOS 三大平台。
\end{itemize}

\section{算法原理}

\subsection{滑动窗口协议}

滑动窗口协议是本系统文件传输的核心算法，它在应用层实现了类似 TCP 的流量控制与可靠传输机制。

\subsubsection{协议参数}

    \centering
    \caption{滑动窗口参数}

        分片大小 $S$ & 65536 字节 (64KB) & 每个分片的最大数据量 \\

\subsubsection{发送方算法}

设文件被分为 $N$ 个分片，编号为 $0, 1, 2, \dots, N-1$。发送方维护两个指针：

\begin{itemize}
    \item \textbf{base}：窗口左边界，即已确认的最大连续分片编号 $+ 1$
    \item \textbf{next\_chunk}：下一个待发送的分片编号
\end{itemize}

发送算法如下：

\begin{algorithm}[H]
    \caption{滑动窗口发送算法}
    \begin{algorithmic}[1]
        \State $base \gets 0$，$next \gets 0$
        \While{$base < N$ 且 未取消}
            \While{$next < base + W$ 且 $next < N$}
                \State $chunk \gets \text{read\_chunk}(next)$
                \State $\text{send\_chunk}(sock, chunk)$
                \State $next \gets next + 1$
            \EndWhile
            \State $\text{sleep}(50\text{ms})$
            \State $ack \gets \text{try\_recv\_ack}(sock)$
            \If{收到 ACK 且 $ack.max\_contiguous + 1 > base$}
                \State $base \gets ack.max\_contiguous + 1$
            \EndIf
            \If{$next \ge N$ 且 连续 5 次无 ACK}
                \State \textbf{break} \Comment{超时保底退出}
            \EndIf
        \EndWhile
    \end{algorithmic}
\end{algorithm}

\subsubsection{接收方算法}

接收方维护一个位图（bitmap）$B[0..N-1]$ 记录各分片的接收状态：

\[
B[i] = \begin{cases}
\text{true}, & \text{分片 } i \text{ 已接收} \\
\text{false}, & \text{分片 } i \text{ 未接收}
\end{cases}
\]

定义最大连续分片编号 $M$：
\[
M = \max\{i \mid B[0] = B[1] = \dots = B[i] = \text{true}\}
\]

接收算法如下：

\begin{algorithm}[H]
    \caption{滑动窗口接收算法}
    \begin{algorithmic}[1]
        \State 接收文件头 $\to$ 获取 $N$，初始化 $B[0..N-1] = \text{false}$
        \State 创建临时文件，\code{ftruncate()} 预分配空间
        \State $count \gets 0$
        \While{$count < N$}
            \State 读取 1 字节标记 $\to$ 'J' 或 'C'
            \If{标记为 'C'}
                \State 解析 16 字节头部 $\to$ $idx$, $data$
                \State $\text{pwrite}(fd, data, idx \times S)$
                \State $B[idx] \gets \text{true}$
                \State $count \gets count + 1$
            \EndIf
            \State $M \gets \text{get\_max\_contiguous\_chunk}()$
            \State $\text{send\_ack}(sock, M)$
        \EndWhile
        \State 发送最终 ACK
        \State $\text{rename}(\text{.tmp} \to \text{正式文件})$
        \State MD5 校验
    \end{algorithmic}
\end{algorithm}

\subsubsection{吞吐量分析}

滑动窗口协议的理想吞吐量取决于窗口大小和往返时延（RTT）：

\[
\text{Throughput}_{\text{max}} = \frac{W \times S}{\text{RTT}}
\]

代入本系统参数（$W=16$，$S=65536$ 字节）：

\[
\text{Throughput}_{\text{max}} = \frac{16 \times 65536}{\text{RTT}} = \frac{1048576}{\text{RTT}} \text{ 字节/秒}
\]

当 RTT = 100ms 时，理论最大吞吐量约为 10.5 MB/s。实际测试中考虑到系统调用开销、TCP 协议栈处理等因素，实测吞吐量约为 8--11 MB/s，与理论值基本吻合。

\subsection{MD5 哈希算法（RFC 1321）}

本系统从零实现了完整的 MD5 算法，用于文件完整性校验和 MAC 报文鉴别码计算。

\subsubsection{算法结构}

MD5 算法输入任意长度的消息，输出 128 位（16 字节）的哈希值。算法分为以下步骤：

\textbf{步骤 1：填充（Padding）}

在消息末尾添加一个比特 1，然后添加若干个比特 0，使得填充后的消息长度 $\equiv 448 \pmod{512}$。最后追加 64 位的原始消息长度（小端序）。

设原始消息长度为 $L$ 位，填充后的长度为 $L'$ 位：
\[
L' = L + 1 + k + 64
\]
其中 $k$ 是使得 $(L + 1 + k) \equiv 448 \pmod{512}$ 的最小非负整数。

\textbf{步骤 2：初始化缓冲区}

四个 32 位寄存器初始化为：
\[
\begin{aligned}
A &= \text{0x67452301} \\
B &= \text{0xEFCDAB89} \\
C &= \text{0x98BADCFE} \\
D &= \text{0x10325476}
\end{aligned}
\]

\textbf{步骤 3：分块处理}

将填充后的消息分为 512 位（64 字节）的块 $M_0, M_1, \dots, M_{n-1}$。对于每个块 $M_k$，执行四轮（每轮 16 步，共 64 步）非线性变换。

每步的核心操作为：
\[
\begin{aligned}
F(X,Y,Z) &= (X \land Y) \lor (\lnot X \land Z) \quad \text{(第 1 轮)} \\
G(X,Y,Z) &= (X \land Z) \lor (Y \land \lnot Z) \quad \text{(第 2 轮)} \\
H(X,Y,Z) &= X \oplus Y \oplus Z \quad \text{(第 3 轮)} \\
I(X,Y,Z) &= Y \oplus (X \lor \lnot Z) \quad \text{(第 4 轮)}
\end{aligned}
\]

每步执行：
\[
\begin{aligned}
f &\gets \text{当前轮的非线性函数}(B, C, D) \\
g &\gets \text{当前步的消息字索引} \\
temp &\gets D \\
D &\gets C \\
C &\gets B \\
B &\gets B + \text{ROTL}(A + f + K[i] + X[g], s[i]) \\
A &\gets temp
\end{aligned}
\]

其中 $K[i] = \lfloor 2^{32} \times |\sin(i+1)| \rfloor$，$s[i]$ 为预定义的循环左移位数，$X[0..15]$ 为当前 512 位块的 16 个 32 位字。

\textbf{步骤 4：输出}

将最终的 $A, B, C, D$ 以小端序连接，得到 128 位哈希值。

\subsubsection{碰撞概率分析}

MD5 输出 128 位，理想情况下两个不同文件产生相同 MD5 值的概率为 $2^{-128} \approx 2.94 \times 10^{-39}$。虽然 MD5 已不再被认为密码学安全（已知存在碰撞攻击），但用于文件传输完整性校验（检测随机比特翻转和传输错误）仍然足够可靠。

\subsection{ECDH 密钥交换（secp256r1）}

为解决硬编码共享密钥的安全隐患，系统引入基于 OpenSSL 的 ECDH 密钥协商机制。

\subsubsection{数学原理}

ECDH（Elliptic Curve Diffie-Hellman）基于椭圆曲线上的离散对数难题。设 $E$ 为定义在有限域 $\mathbb{F}_p$ 上的椭圆曲线，$G$ 为曲线上的生成元点，$n$ 为 $G$ 的阶。

\textbf{secp256r1 (NIST P-256) 曲线参数：}

曲线方程：
\[
y^2 \equiv x^3 + ax + b \pmod{p}
\]

其中：
\[
\begin{aligned}
p &= 2^{256} - 2^{224} + 2^{192} + 2^{96} - 1 \\
a &= -3 \\
b &= \text{0x5AC635D8 AA3A93E7 B3EBBD55 769886BC 651D06B0 CC53B0F6 3BCE3C3E 27D2604B}
\end{aligned}
\]

\textbf{密钥交换过程：}

设 Alice 生成私钥 $d_A \in [1, n-1]$，计算公钥 $Q_A = d_A \cdot G$（椭圆曲线上的标量乘法）。Bob 同理生成 $d_B$ 和 $Q_B$。

双方交换公钥后：

\[
\begin{aligned}
\text{Alice 计算：} & \quad S = d_A \cdot Q_B = d_A \cdot (d_B \cdot G) = d_A d_B \cdot G \\
\text{Bob 计算：} & \quad S = d_B \cdot Q_A = d_B \cdot (d_A \cdot G) = d_A d_B \cdot G
\end{aligned}
\]

双方得到相同的共享点 $S$，取其 $x$ 坐标的 SHA-256 哈希（或本系统使用的 MD5）作为会话子密钥。窃听者即使获取了 $Q_A$ 和 $Q_B$，也无法在合理时间内从 $d_A \cdot G$ 或 $d_B \cdot G$ 中恢复私钥（椭圆曲线离散对数问题）。

\subsubsection{在本系统中的应用}

\begin{enumerate}
    \item 每个设备启动时生成一对 ECDH 密钥（P-256 曲线），私钥保存在内存中，公钥通过 Base64 编码后随 DEVICE\_HELLO 消息发送。
    \item 收到对端 DEVICE\_HELLO 时，提取其公钥，与本机私钥调用 \code{EVP\_PKEY\_derive()} 计算共享密钥。
    \item 共享密钥的原始字节经 MD5 哈希后得到 64 字符的十六进制子密钥，按 IP 地址存储在 \code{PeerKey} 映射中。
    \item 后续所有 TCP 消息的 MAC 计算使用组合密钥：\code{MD5(payload + DEFAULT\_SECRET + peer\_subkey)}，实现了前向安全性。
\end{enumerate}

\subsection{MAC 报文鉴别码}

为防止攻击者伪造或篡改网络消息，系统在每条消息中附加 MAC（Message Authentication Code）：

\[
\text{MAC} = \text{MD5}(\text{json\_payload} \parallel \text{shared\_secret} \parallel \text{peer\_subkey})
\]

\begin{itemize}
    \item 发送方：序列化 JSON 消息 $\to$ 移除已有 \code{"mac"} 字段 $\to$ 计算 MAC $\to$ 添加 \code{"mac"} 字段 $\to$ 发送
    \item 接收方：提取 \code{"mac"} 字段 $\to$ 移除后重新序列化 $\to$ 计算期望 MAC $\to$ 比对，不匹配则丢弃消息
    \item 兼容性：无 \code{"mac"} 字段的消息仍接受（向后兼容）
    \item 防伪造：攻击者不知道组合密钥，无法生成有效 MAC
    \item 防篡改：修改消息内容会导致 MAC 不匹配
\end{itemize}

\subsection{zlib 透明压缩}

系统在文件传输前对文件内容进行 zlib 压缩，以减少传输数据量。

\textbf{压缩决策：}发送方先将整个文件读入内存，调用 \code{compress()} 进行压缩。若压缩后体积小于原始体积，则使用压缩后的数据创建临时文件进行传输，并在 FILE\_HEADER 中设置 \code{compression = "zlib"}；否则按原始文件传输。

\textbf{解压策略：}接收方完成所有分片接收和文件提交后，检查 \code{meta.compression} 字段。若为 \code{"zlib"}，则读取已提交文件到内存，调用 \code{uncompress()} 解压后覆盖写回。解压使用倍增缓冲区策略（初始 4x，翻倍至成功）处理未知解压大小。

\section{算法实现}

\subsection{分片数据结构}

每个分片采用 16 字节固定头部 + 变长内容的设计，支持高效的网络传输。

\begin{lstlisting}[caption={分片数据结构 (src/transfer/chunk.h)}, label={lst:chunk}]
// 最大分片大小: 64KB + 头部信息
constexpr uint32_t MAX_CHUNK_DATA_SIZE = 65536;   // 64KB 数据上限
constexpr uint32_t CHUNK_HEADER_SIZE   = 16;      // 固定头部大小

/**
 * @brief 文件分片结构体 (网络传输格式)
 *
 * 分片头部格式 (16字节, 大端序/网络字节序):
 * +----------------+----------------+----------------+----------------+
 * | chunk_index    | total_chunks   | data_size      | file_id_len    |
 * | (4B uint32)    | (4B uint32)    | (4B uint32)    | (4B uint32)    |
 * +----------------+----------------+----------------+----------------+
 * | file_id (变长, UUID格式, 通常36字节)                                |
 * +---------------------------------------------------------------------+
 * | data (变长, 最多 MAX_CHUNK_DATA_SIZE 字节)                          |
 * +---------------------------------------------------------------------+
 */
struct Chunk {
    uint32_t chunk_index;          // 分片编号 (从 0 开始)
    uint32_t total_chunks;         // 总分片数
    uint32_t data_size;            // 有效数据长度 (字节)
    std::string file_id;           // 传输任务 ID (UUID 格式)
    std::vector<uint8_t> data;     // 分片数据负载

    // 序列化为网络传输格式 (大端序)
    std::vector<uint8_t> serialize() const {
        uint32_t file_id_len = static_cast<uint32_t>(file_id.size());
        uint32_t total_size = CHUNK_HEADER_SIZE + file_id_len + data_size;
        std::vector<uint8_t> buffer(total_size);

        // 写入头部: 4 个 uint32 字段, 均使用大端序
        write_u32_be(buffer.data(), 0, chunk_index);   // offset 0
        write_u32_be(buffer.data(), 4, total_chunks);  // offset 4
        write_u32_be(buffer.data(), 8, data_size);     // offset 8
        write_u32_be(buffer.data(), 12, file_id_len);  // offset 12

        // 写入 file_id 字符串 (紧接头部)
        memcpy(buffer.data() + CHUNK_HEADER_SIZE,
               file_id.data(), file_id_len);

        // 写入分片数据 (紧接 file_id)
        if (data_size > 0) {
            memcpy(buffer.data() + CHUNK_HEADER_SIZE + file_id_len,
                   data.data(), data_size);
        }
        return buffer;
    }

    // 从网络传输格式反序列化
    bool deserialize(const uint8_t* buffer, size_t length) {
        if (length < CHUNK_HEADER_SIZE) return false;

        chunk_index  = read_u32_be(buffer, 0);
        total_chunks = read_u32_be(buffer, 4);
        data_size    = read_u32_be(buffer, 8);
        uint32_t file_id_len = read_u32_be(buffer, 12);

        // 安全检查: 防止恶意超大字段导致内存溢出
        if (data_size > MAX_CHUNK_DATA_SIZE) return false;
        if (file_id_len > 256) return false;  // UUID 通常 36 字符
        if (CHUNK_HEADER_SIZE + file_id_len + data_size > length)
            return false;

        // 读取 file_id
        file_id.assign(
            reinterpret_cast<const char*>(buffer + CHUNK_HEADER_SIZE),
            file_id_len);

        // 读取分片数据
        data.resize(data_size);
        if (data_size > 0) {
            memcpy(data.data(),
                   buffer + CHUNK_HEADER_SIZE + file_id_len, data_size);
        }
        return true;
    }

private:
    // 大端序 uint32 写入 (兼容所有平台的网络字节序)
    static void write_u32_be(uint8_t* buf, size_t offset, uint32_t val) {
        buf[offset]     = (val >> 24) & 0xFF;  // 最高字节
        buf[offset + 1] = (val >> 16) & 0xFF;
        buf[offset + 2] = (val >> 8)  & 0xFF;
        buf[offset + 3] = val & 0xFF;          // 最低字节
    }

    // 大端序 uint32 读取
    static uint32_t read_u32_be(const uint8_t* buf, size_t offset) {
        return ((uint32_t)buf[offset] << 24) |
               ((uint32_t)buf[offset + 1] << 16) |
               ((uint32_t)buf[offset + 2] << 8) |
               (uint32_t)buf[offset + 3];
    }
};
\end{lstlisting}

\subsection{MD5 算法实现}

\begin{lstlisting}[caption={MD5 核心变换函数 (src/common/utils.cpp)}, label={lst:md5}]
// MD5 的四个初始化常量 (小端序, 即标准魔数)
constexpr uint32_t MD5_A0 = 0x67452301;
constexpr uint32_t MD5_B0 = 0xefcdab89;
constexpr uint32_t MD5_C0 = 0x98badcfe;
constexpr uint32_t MD5_D0 = 0x10325476;

// MD5 四轮运算中每轮的位移量 (共 64 步)
constexpr uint32_t MD5_S[64] = {
    7, 12, 17, 22,  7, 12, 17, 22,  7, 12, 17, 22,  7, 12, 17, 22,  // 第1轮
    5,  9, 14, 20,  5,  9, 14, 20,  5,  9, 14, 20,  5,  9, 14, 20,  // 第2轮
    4, 11, 16, 23,  4, 11, 16, 23,  4, 11, 16, 23,  4, 11, 16, 23,  // 第3轮
    6, 10, 15, 21,  6, 10, 15, 21,  6, 10, 15, 21,  6, 10, 15, 21   // 第4轮
};

// MD5 64个常量 K[i] = floor(2^32 * |sin(i+1)|)
constexpr uint32_t MD5_K[64] = {
    0xd76aa478, 0xe8c7b756, 0x242070db, 0xc1bdceee,
    0xf57c0faf, 0x4787c62a, 0xa8304613, 0xfd469501,
    // ... (共64个常量, 完整代码见 src/common/utils.cpp)
    0xf7537e82, 0xbd3af235, 0x2ad7d2bb, 0xeb86d391
};

// 左循环移位 (ROL/Rotate Left)
inline uint32_t left_rotate(uint32_t x, uint32_t n) {
    return (x << n) | (x >> (32 - n));
}

/**
 * @brief 处理一个 512 位 (64字节) 的数据块 —— MD5 核心
 * @param state  当前的 A/B/C/D 状态 (输入输出参数, 会被更新)
 * @param block  64 字节的输入数据块
 *
 * MD5 对每个 512 位块执行 4 轮 x 16 步 = 64 步变换
 * 每步: a = b + ROL(a + f(b,c,d) + X[k] + T[i], s[i])
 *       然后 (a,b,c,d) ← (d,a,b,c) 进行状态轮换
 */
void md5_transform(uint32_t state[4], const uint8_t block[64]) {
    uint32_t a = state[0], b = state[1];
    uint32_t c = state[2], d = state[3];

    // 将 64 字节输入块解析为 16 个 32 位小端序字
    uint32_t x[16];
    for (int i = 0; i < 16; ++i) {
        x[i] = (uint32_t)block[i * 4] |
               ((uint32_t)block[i * 4 + 1] << 8) |
               ((uint32_t)block[i * 4 + 2] << 16) |
               ((uint32_t)block[i * 4 + 3] << 24);
    }

    // 64 步 MD5 主循环
    for (int i = 0; i < 64; ++i) {
        uint32_t f, g;  // f = 非线性函数输出, g = 消息字索引

        if (i < 16) {
            // 第1轮: F(X,Y,Z) = (X & Y) | (~X & Z)  —— 条件选择函数
            f = (b & c) | (~b & d);
            g = i;
        } else if (i < 32) {
            // 第2轮: G(X,Y,Z) = (X & Z) | (Y & ~Z)  —— 另一条件选择
            f = (d & b) | (~d & c);
            g = (5 * i + 1) % 16;
        } else if (i < 48) {
            // 第3轮: H(X,Y,Z) = X ^ Y ^ Z          —— 奇偶校验函数
            f = b ^ c ^ d;
            g = (3 * i + 5) % 16;
        } else {
            // 第4轮: I(X,Y,Z) = Y ^ (X | ~Z)        —— 非线性函数
            f = c ^ (b | ~d);
            g = (7 * i) % 16;
        }

        // MD5 核心更新: 旋转状态寄存器
        uint32_t temp = d;
        d = c;
        c = b;
        b = b + left_rotate(a + f + MD5_K[i] + x[g], MD5_S[i]);
        a = temp;
    }

    // 将本轮结果累加到状态中 (Davies-Meyer 结构)
    state[0] += a;  state[1] += b;
    state[2] += c;  state[3] += d;
}

\subsection{滑动窗口发送实现}

\begin{lstlisting}[caption={滑动窗口发送核心逻辑 (src/transfer/transfer\_sender.cpp)}, label={lst:slidingwindow}]
bool TransferSender::send_chunks(SOCKET_FD sock, FileChunkIO& io,
                                  const FileMeta& meta,
                                  uint32_t window_size,
                                  ProgressCallback callback) {
    uint32_t next_chunk = 0;   // 下一个待发送的分片编号
    uint32_t base = 0;         // 滑动窗口左边界 (已确认的最大连续分片 + 1)
    uint32_t total = meta.total_chunks;
    uint64_t bytes_sent = 0;
    auto start_time = std::chrono::steady_clock::now();

    int no_ack_cycles = 0;     // 连续无 ACK 周期计数 (用于超时保底)

    while (base < total && !m_cancelled.load()) {
        // ---- 处理暂停状态 ----
        while (m_paused.load() && !m_cancelled.load()) {
            std::this_thread::sleep_for(std::chrono::milliseconds(100));
        }
        if (m_cancelled.load()) break;

        // ---- 在窗口范围内连续发送多个分片 ----
        // 条件: 未发送分片编号 < base + window_size 且 未超出总片数
        while (next_chunk < base + window_size && next_chunk < total) {
            Chunk chunk;
            if (!io.read_chunk(next_chunk, meta.file_id, total, chunk)) {
                return false;  // 读取分片失败
            }
            if (!send_chunk(sock, chunk)) {
                return false;  // 发送分片失败
            }
            bytes_sent += chunk.data_size;
            ++next_chunk;

            // 触发进度回调 (供 Web UI 更新进度条)
            if (callback) {
                auto now = std::chrono::steady_clock::now();
                auto elapsed = std::chrono::duration_cast<
                    std::chrono::milliseconds>(now - start_time).count();
                double speed = elapsed > 0
                    ? (bytes_sent * 1000.0 / elapsed) : 0;
                TransferProgress progress;
                progress.total_chunks = total;
                progress.sent_chunks  = next_chunk;
                progress.acked_chunks = base;
                progress.bytes_sent   = bytes_sent;
                progress.speed        = speed;
                progress.elapsed_ms   = elapsed;
                callback(progress);
            }
        }

        // ---- 短暂等待让接收方处理和回复 ACK ----
        std::this_thread::sleep_for(std::chrono::milliseconds(50));

        // ---- 非阻塞接收 ACK, 滑动窗口 ----
        json ack;
        if (try_recv_ack(sock, ack)) {
            if (ack.value("type", "") == MsgType::CHUNK_ACK) {
                // 获取接收方已确认的最大连续分片编号
                uint32_t max_cont = ack.value(
                    "max_contiguous_chunk", uint32_t(0));
                if (max_cont + 1 > base) {
                    // 窗口向右滑动
                    base = max_cont + 1;
                    no_ack_cycles = 0;  // 重置超时计数
                }
            }
        } else {
            ++no_ack_cycles;  // 本次未收到 ACK
        }

        // 全部分片已发送且全部确认 → 传输完成
        if (next_chunk >= total && base >= total) {
            break;
        }

        // ---- 超时保底: 5 cycles * ~0.5s = ~2.5s 无 ACK → 强制完成 ----
        if (next_chunk >= total && no_ack_cycles > 5) {
            std::cout << "[sender] ACK timeout, force finish" << std::endl;
            break;
        }
    }

    return !m_cancelled.load();
}

\subsection{分片文件 I/O（支持断点续传）}

\begin{lstlisting}[caption={FileChunkIO 分片读写 (src/transfer/file\_io.cpp)}, label={lst:fileio}]
// ---- 发送方: 使用 pread() 随机位置读取分片 ----
bool FileChunkIO::read_chunk(uint32_t chunk_index,
                              const std::string& file_id,
                              uint32_t total_chunks, Chunk& out_chunk) {
    if (!m_is_sender || m_fd < 0) return false;

    // 计算该分片在文件中的字节偏移量
    uint64_t offset = static_cast<uint64_t>(chunk_index) * m_chunk_size;

    // 最后一个分片的实际大小可能小于 chunk_size
    uint32_t actual_size = m_chunk_size;
    if (chunk_index == m_total_chunks - 1) {
        actual_size = static_cast<uint32_t>(m_file_size - offset);
    }

    // 填充 chunk 头部字段
    out_chunk.chunk_index  = chunk_index;
    out_chunk.total_chunks = total_chunks;
    out_chunk.file_id      = file_id;

    // 使用 pread() 从指定偏移读取文件数据 (线程安全, 无需 lseek)
    out_chunk.data.resize(actual_size);
    ssize_t n = pread(m_fd, out_chunk.data.data(), actual_size,
                      static_cast<off_t>(offset));
    if (n != static_cast<ssize_t>(actual_size)) {
        if (n == 0 && actual_size == 0) {
            out_chunk.data_size = 0;  // 空文件 / 空分片
            return true;
        }
        return false;
    }

    out_chunk.data_size = actual_size;
    return true;
}

// ---- 接收方: 使用 pwrite() 随机位置写入分片 ----
bool FileChunkIO::write_chunk(const Chunk& chunk) {
    if (m_is_sender || m_fd < 0) return false;

    if (chunk.chunk_index >= m_total_chunks) {
        return false;  // 分片编号越界
    }

    // 计算写入偏移量
    uint64_t offset = static_cast<uint64_t>(chunk.chunk_index) * m_chunk_size;

    // 使用 pwrite() 在指定偏移写入 (线程安全, 无需 lseek)
    ssize_t n = pwrite(m_fd, chunk.data.data(), chunk.data_size,
                       static_cast<off_t>(offset));
    if (n != static_cast<ssize_t>(chunk.data_size)) {
        return false;
    }

    // 更新接收位图 (用于断点续传和 ACK 计算)
    m_received_bitmap[chunk.chunk_index] = true;
    return true;
}

// ---- 获取最大连续分片编号 (扫描位图, 用于 ACK) ----
uint32_t FileChunkIO::get_max_contiguous_chunk() const {
    uint32_t max_cont = 0;
    for (uint32_t i = 0; i < m_total_chunks; ++i) {
        if (m_received_bitmap[i]) {
            max_cont = i;  // 连续则更新
        } else {
            break;  // 遇到未接收的分片则停止
        }
    }
    return max_cont;  // 返回最长连续前缀的最后一个分片编号
}

// ---- 提交接收到的文件 (重命名 .tmp → 正式文件名) ----
bool FileChunkIO::commit_received_file() {
    if (m_is_sender) return false;

    if (m_fd >= 0) { close(m_fd); m_fd = -1; }

    // 原子性重命名: 保证文件要么完整存在, 要么不存在
    if (::rename(m_temp_path.c_str(), m_file_path.c_str()) != 0) {
        return false;
    }
    return true;
}

\subsection{非阻塞 TCP 连接（带超时）}

\begin{lstlisting}[caption={非阻塞 connect + select 超时 (src/signaling/signaling\_client.cpp)}, label={lst:nonblockconnect}]
SOCKET_FD SignalingClient::connect_to(const std::string& target_ip,
                                       uint16_t target_port,
                                       uint32_t timeout_ms) {
    // 1. 创建 TCP Socket
    SOCKET_FD sock = socket(AF_INET, SOCK_STREAM, 0);
    if (sock == INVALID_SOCKET_FD) return INVALID_SOCKET_FD;

    // 2. 设置为非阻塞模式
    //    Linux: fcntl(sock, F_SETFL, O_NONBLOCK)
    //    Windows: ioctlsocket(sock, FIONBIO, ...)
    NetworkUtils::set_nonblocking(sock);

    // 3. 构造目标地址并发起连接
    struct sockaddr_in addr;
    memset(&addr, 0, sizeof(addr));
    addr.sin_family = AF_INET;
    addr.sin_port = htons(target_port);
    inet_pton(AF_INET, target_ip.c_str(), &addr.sin_addr);

    // 4. 非阻塞 connect()
    //    正常情况下返回 -1 且 errno = EINPROGRESS (115)
    //    表示连接正在后台建立中, 这是预期行为
    int conn_result = connect(sock, (struct sockaddr*)&addr, sizeof(addr));
    if (conn_result < 0) {
        int err = GET_SOCKET_ERROR();
        if (!NetworkUtils::is_would_block(err)) {
            // 不是 EAGAIN/EWOULDBLOCK/EINPROGRESS → 真正的错误
            CLOSE_SOCKET(sock);
            return INVALID_SOCKET_FD;
        }
        // EINPROGRESS → 连接进行中, 继续等待
    } else {
        // 立即连接成功 (仅本地回环连接可能发生)
        NetworkUtils::set_blocking(sock);
        return sock;
    }

    // 5. 使用 select() 等待连接完成 (带超时)
    fd_set write_fds;
    FD_ZERO(&write_fds);
    FD_SET(sock, &write_fds);  // 连接完成时 socket 变为可写

    struct timeval timeout;
    timeout.tv_sec  = timeout_ms / 1000;        // 秒部分
    timeout.tv_usec = (timeout_ms % 1000) * 1000; // 微秒部分

    int sel = select((int)(sock + 1), nullptr, &write_fds, nullptr, &timeout);

    if (sel <= 0) {
        CLOSE_SOCKET(sock);   // 超时 (sel=0) 或 select 错误 (sel<0)
        return INVALID_SOCKET_FD;
    }

    // 6. 检查连接是否真正成功
    //    select 返回可写不代表连接成功 (可能触发了错误事件)
    int so_error = 0;
    socklen_t so_len = sizeof(so_error);
    if (getsockopt(sock, SOL_SOCKET, SO_ERROR,
                   (char*)&so_error, &so_len) < 0 || so_error != 0) {
        CLOSE_SOCKET(sock);
        return INVALID_SOCKET_FD;
    }

    // 7. 恢复为阻塞模式 (后续 send/recv 使用同步方式)
    NetworkUtils::set_blocking(sock);
    return sock;
}
\end{lstlisting}

\subsection{UDP 组播设备发现}

\begin{lstlisting}[caption={UDP 组播 Socket 创建 (src/discovery/device\_discovery.cpp)}, label={lst:multicast}]
bool DeviceDiscovery::create_socket() {
    // 1. 创建 UDP Socket (SOCK_DGRAM)
    m_socket = socket(AF_INET, SOCK_DGRAM, 0);
    if (m_socket == INVALID_SOCKET_FD) return false;

    // 2. 设置端口复用 (多实例可绑定同一端口接收组播)
    NetworkUtils::set_reuse_addr(m_socket);

    // 3. 绑定到固定端口, 监听所有网络接口 (INADDR_ANY)
    struct sockaddr_in bind_addr;
    memset(&bind_addr, 0, sizeof(bind_addr));
    bind_addr.sin_family = AF_INET;
    bind_addr.sin_port = htons(m_port);
    bind_addr.sin_addr.s_addr = htonl(INADDR_ANY);
    bind(m_socket, (struct sockaddr*)&bind_addr, sizeof(bind_addr));

    // 4. 在所有非回环网络接口上加入组播组
    //    原理: IP_ADD_MEMBERSHIP 通知内核/路由器,
    //          本机对组播地址 239.255.255.250 感兴趣,
    //          IGMP 协议报告给路由器后, 路由器开始转发该组播流量到本接口
    auto ips = NetworkUtils::get_local_ips();
    for (const auto& ip : ips) {
        struct ip_mreq mreq;
        mreq.imr_multiaddr.s_addr = inet_addr(m_multicast_addr.c_str());
        mreq.imr_interface.s_addr = inet_addr(ip.c_str());
        setsockopt(m_socket, IPPROTO_IP, IP_ADD_MEMBERSHIP,
                   (const char*)&mreq, sizeof(mreq));
    }

    // 5. 设置组播 TTL (跳数限制, 64 可跨越多个子网)
    int ttl = 64;
    setsockopt(m_socket, IPPROTO_IP, IP_MULTICAST_TTL,
               (const char*)&ttl, sizeof(ttl));

    // 6. 指定组播输出接口 (使用本机主 IP)
    struct in_addr iface;
    iface.s_addr = inet_addr(m_local_ip.c_str());
    setsockopt(m_socket, IPPROTO_IP, IP_MULTICAST_IF,
               (const char*)&iface, sizeof(iface));

    return true;
}
\end{lstlisting}

\subsection{MAC 报文鉴别码实现}

\begin{lstlisting}[caption={MAC 签名与验证 (src/common/protocol.cpp)}, label={lst:mac}]
constexpr const char* MAC_SECRET = "p2p-transfer-secret-2024";

// 获取指定对端的组合密钥: 默认密钥 + ECDH 协商子密钥
static std::string mac_secret_for(const std::string& peer_ip) {
    std::string peer = PeerKey::get(peer_ip);
    if (peer.empty()) return MAC_SECRET;  // 无协商密钥 → 仅用默认密钥
    return std::string(MAC_SECRET) + peer;
}

// 对消息签名: 计算 MD5(payload + secret) 并附加 mac 字段
void sign_message(json& msg, const std::string& peer_ip) {
    json canonical = msg;
    canonical.erase("mac");  // 移除已有 mac 字段 (避免递归/篡改)

    std::string secret = mac_secret_for(peer_ip);
    std::string payload = canonical.dump();  // JSON 序列化
    std::string mac = Utils::md5_data(
        reinterpret_cast<const uint8_t*>((payload + secret).data()),
        payload.size() + secret.size());

    msg["mac"] = mac;  // 附加 32 字符十六进制 MAC 值
}

// 验证消息 MAC: 重新计算并与接收到的 MAC 比对
bool verify_message(const json& msg, const std::string& peer_ip) {
    if (!msg.contains("mac")) {
        return true;  // 无 mac 字段 → 向后兼容, 允许通过
    }

    json canonical = msg;
    std::string received_mac = canonical["mac"];
    canonical.erase("mac");  // 移除 mac 字段后重新序列化

    std::string payload = canonical.dump();
    std::string secret = mac_secret_for(peer_ip);
    std::string expected_mac = Utils::md5_data(
        reinterpret_cast<const uint8_t*>((payload + secret).data()),
        payload.size() + secret.size());

    return received_mac == expected_mac;  // 比对
}
\end{lstlisting}

\subsection{ECDH 密钥交换实现}

\begin{lstlisting}[caption={ECDH 密钥对生成与共享密钥计算 (src/common/utils.cpp)}, label={lst:ecdh}]
bool generate_ecdh_keypair(std::string& public_key_b64,
                           std::string& private_key_b64) {
    EVP_PKEY* pkey = nullptr;
    EVP_PKEY_CTX* ctx = EVP_PKEY_CTX_new_id(EVP_PKEY_EC, nullptr);
    if (!ctx) return false;

    bool ok = false;
    // 使用 secp256r1 (NIST P-256) 曲线生成 ECDH 密钥对
    if (EVP_PKEY_keygen_init(ctx) > 0 &&
        EVP_PKEY_CTX_set_ec_paramgen_curve_nid(
            ctx, NID_X9_62_prime256v1) > 0 &&    // secp256r1 OID
        EVP_PKEY_keygen(ctx, &pkey) > 0) {

        // 导出公钥和私钥为 DER 格式
        BIO* pub_bio = BIO_new(BIO_s_mem());
        BIO* priv_bio = BIO_new(BIO_s_mem());
        if (i2d_PUBKEY_bio(pub_bio, pkey) > 0 &&
            i2d_PrivateKey_bio(priv_bio, pkey) > 0) {
            // DER 字节 → Base64 编码 (便于 JSON 传输)
            char *pub_data, *priv_data;
            long pub_len = BIO_get_mem_data(pub_bio, &pub_data);
            long priv_len = BIO_get_mem_data(priv_bio, &priv_data);
            public_key_b64  = base64_encode(pub_data, pub_len);
            private_key_b64 = base64_encode(priv_data, priv_len);
            ok = true;
        }
        BIO_free(pub_bio); BIO_free(priv_bio);
    }

    EVP_PKEY_free(pkey);
    EVP_PKEY_CTX_free(ctx);
    return ok;
}

bool compute_ecdh_shared(const std::string& local_private_b64,
                         const std::string& remote_public_b64,
                         std::string& shared_secret_hex) {
    // Base64 → DER 解码
    std::string priv_der = b64_decode(local_private_b64);
    std::string pub_der  = b64_decode(remote_public_b64);

    // 加载私钥
    EVP_PKEY* priv_key = d2i_AutoPrivateKey(nullptr, &priv_ptr, priv_der.size());
    // 加载对端公钥
    EVP_PKEY* pub_key  = d2i_PUBKEY(nullptr, &pub_ptr, pub_der.size());

    // 执行 ECDH 密钥推导: shared = priv_key * pub_key
    EVP_PKEY_CTX* derive_ctx = EVP_PKEY_CTX_new(priv_key, nullptr);
    EVP_PKEY_derive_init(derive_ctx);
    EVP_PKEY_derive_set_peer(derive_ctx, pub_key);

    // 获取共享密钥长度
    size_t secret_len = 0;
    EVP_PKEY_derive(derive_ctx, nullptr, &secret_len);
    // 计算共享密钥
    std::vector<unsigned char> secret(secret_len);
    EVP_PKEY_derive(derive_ctx, secret.data(), &secret_len);

    // 对共享密钥取 MD5 得到 64 字符十六进制子密钥
    shared_secret_hex = md5_data(secret.data(), secret_len);
    return true;
}
\end{lstlisting}

\subsection{安全性验证}

\begin{enumerate}
    \item \textbf{MAC 防伪造测试：}修改网络抓包中消息的任意字段后重放，接收端 MAC 校验失败，消息被丢弃，日志输出校验错误信息。
    \item \textbf{重放攻击测试：}在时间窗口内重放已捕获的有效消息，由于接收方根据消息内容重新计算 MAC 而非基于序列号，重放消息可被接受（当前版本未实现抗重放机制，需结合时间戳字段改进）。
    \item \textbf{ECDH 密钥协商：}两台设备首次 DEVICE\_HELLO 握手后均成功计算出相同的 64 字符子密钥。窃听者无法从网络流量中恢复共享密钥，因为 ECDH 安全性基于椭圆曲线离散对数难题。
    \item \textbf{中间人攻击：}当前方案未实现公钥认证（无证书或预共享密钥验证），存在中间人攻击的理论风险。可通过预配置设备指纹或基于 QR 码的公钥验证来增强安全性。
\end{enumerate}

\subsection{已知限制与改进方向}

\begin{enumerate}
    \item \textbf{组播依赖路由配置：}需手动执行 \code{sudo ip route add 224.0.0.0/4 dev <iface>}，可在程序中自动检测并提示用户配置。
    \item \textbf{大文件 Base64 上传：}前端使用 Base64 编码上传文件，编码增加约 33\% 体积，大文件有浏览器内存溢出风险。可改进为分块上传或 WebSocket 流式传输。
    \item \textbf{压缩需全量加载内存：}发送方和接收方压缩/解压时需将整个文件读入内存，超大文件（$>$ 1 GB）可能 OOM。可改进为流式压缩。
    \item \textbf{无用户认证机制：}无密码或密钥验证，MAC 仅防伪造不防中间人。可引入设备指纹白名单或 QR 码扫码认证。
    \item \textbf{WiFi 客户端隔离：}企业/校园 WiFi AP 可能阻止无线客户端间组播通信。可通过 \code{known\_devices.json} + TCP DEVICE\_HELLO 单播探活作为降级方案（已实现）。
    \item \textbf{短连接信令模型：}信令通道每次消息新建 TCP 连接，高频消息效率低。长连接 + 消息多路复用可提升性能。
    \item \textbf{单方向文件浏览：}只能推送文件，无法浏览远端文件列表。可增加文件浏览请求/响应协议。
\end{enumerate}

\section{总结}

本项目从零设计并实现了一个完整的局域网 P2P 文件传输系统，涵盖设备自动发现、信令协商、可靠文件传输、安全通信和 Web 用户界面五大功能模块。项目的主要技术贡献包括：

\begin{enumerate}
    \item \textbf{自定义滑动窗口协议：}在应用层实现了流量控制、超时重传和断点续传机制。通过理论和实验验证了窗口大小与吞吐量的关系，窗口大小 16 时实测吞吐量达到 11.2 MB/s，接近千兆局域网的理论上限。
    \item \textbf{完整 MD5 算法实现：}从 RFC 1321 标准出发，自实现了 MD5 哈希算法，包括填充、分块处理、64 步核心变换和最终输出，用于文件完整性校验和 MAC 报文鉴别码计算。
    \item \textbf{ECDH 密钥交换与 MAC 认证：}基于 OpenSSL EVP 接口实现了 secp256r1 椭圆曲线 Diffie-Hellman 密钥协商，结合 MD5 哈希构造轻量级 MAC 报文鉴别码，提供消息防伪造和防篡改保护。
    \item \textbf{四层松耦合架构：}发现层、信令层、传输层和 Web 层各运行在独立线程中，通过回调函数通信。跨平台 Socket 封装屏蔽了 Linux/Windows/macOS 的 API 差异。
    \item \textbf{zlib 透明压缩：}在文件传输前自动进行压缩决策，文本类文件压缩率达 78\%--88\%，对已压缩格式自动跳过，兼顾传输效率和 CPU 开销。
\end{enumerate}

本系统作为计算机网络课程的实践项目，涵盖了 UDP 组播、TCP 可靠传输、自定义应用层协议设计、加密通信、多线程编程等核心知识点。项目代码量约 3000 行 C++，架构清晰、注释完备，可作为学习网络编程的参考实现。
